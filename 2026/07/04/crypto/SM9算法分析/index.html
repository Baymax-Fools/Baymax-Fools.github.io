SM9算法分析（国密学习5/5）

注：本blog参考《SM9标识密码算法 第1部分：总则》(GB/T 38635.1-2020)、《SM9标识密码算法 第2部分：算法》(GB/T 38635.2-2020)与python开源库gmssl的实现

国家标准全文公开系统：https://openstd.samr.gov.cn

SM9 的完整实现代码我就不放了，pairing 那部分 $\mathbb{F}_{q^{12}}$ 塔式运算加 Miller loop 手写出来太长，看着乱（想啃的去看 38635.1 附录B，R-ate pairing 的完整伪代码都在里面），验证代码那节给的是能直接跑的参数检查加标准向量对拍。

算法基本信息

SM9 是标识密码算法（IBC，Identity-Based Cryptography），对标的是传统 PKI 那一整套（证书、CA，签名对应 ECDSA，密钥交换对应 ECDH，加密对应 ECIES）。核心区别就一句话：公钥直接用身份标识。ID 可以是邮箱、手机号这种随便什么字符串，不用证书来绑定了，私钥由一个 KGC（密钥生成中心）统一算出来发给用户。这个想法是 Shamir 1984 年提出的（IBC 的开山），SM9 就是国密给它的标准化答案，对标 RFC 5091 那一族。

组成部分（对标着看）：

(1) 数字签名（38635.2 第6章），对标 ECDSA

(2) 密钥交换（第7章），对标 ECDH

(3) 密钥封装（第8章），对标 ECIES 的 KEM

(4) 公钥加密（第9章），对标 ECIES

和 SM2 最大的不同是 SM9 用了双线性对（pairing）：$e: G_1 \times G_2 \to G_T$。$G_1$ 是 $E(\mathbb{F}_q)$ 上的 $N$ 阶加法循环群，$G_2$ 是扭曲线 $E'(\mathbb{F}_{q^2})$ 上的 $N$ 阶加法循环群，$G_T$ 是 $\mathbb{F}_{q^{12}}$ 上的 $N$ 阶乘法循环群，嵌入次数 $k=12$。双线性就一条 $e([a]P, [b]Q) = e(P, Q)^{ab}$，SM9 全部协议的正确性都是拿这一条配出来的（后面每个协议我都给一行推完的推导）。随机数生成要求参考 GB/T 32915。

GB/T 38635.2中写： 系统参数组包括曲线识别符 cid、有限域参数、曲线 $E(\mathbb{F}_q)$ 参数、扭曲线参数 $\beta$、素因子 $N$、余因子 $cf$、嵌入次数 $k$、生成元 $P_1$（$G_1$）、生成元 $P_2$（$G_2$）、双线性对识别符 eid 以及可选的 $G_2$ 到 $G_1$ 的同态映射 $\psi$。

SM9 用的曲线是 BN 曲线（Barreto–Naehrig 2005），$y^2 = x^3 + b$，$a = 0$，这种曲线族天然 $k = 12$，pairing 效率好。

数字签名算法

主密钥和用户私钥

SM9 的私钥不是用户自己随机生成的，是 KGC 发的。KGC 先生成签名主密钥：随机 $k_s \in [1, N-1]$，算

$P_{pub\text{-}s} = [k_s]P_2$

注意这是 $G_2$ 的点，方向别记反了（加密体系那边正好反过来，密钥交换那节再说）。用户 A 的签名私钥：

$t_1 = (H_1(ID_A \Vert hid, N) + k_s) \bmod N$（$t_1 = 0$ 的话主密钥作废重来，所有用户私钥重发）

$t_2 = k_s \cdot t_1^{-1} \bmod N$

$d_{sA} = [t_2]P_1$（$G_1$ 的点，KGC 把它发给用户，$t_2$ 是中间量不外发，从 $d_{sA}$ 反推 $t_2$ 就是解 ECDLP）

核心恒等式就一条：$t_2 \cdot (H_1(ID_A \Vert hid, N) + k_s) = k_s$。私钥派生是拿 $H_1 + k_s$ 的逆去乘 $k_s$，验证算法本质就是拿 pairing 把这个式子还原回去（下面有推导）。hid 是一个字节的函数识别符做域分离，签名的例子用 01。

$H_1$、$H_2$ 是把任意字节串 hash 进 $[1, N-1]$ 的函数，构造是 SM3 出块拼串：设 $ct = 1$，$hlen = 8\lceil 5\log_2 n / 32 \rceil$，每轮算 $Ha_i = H_v(01 \Vert Z \Vert ct)$ 然后 $ct$ 加一，拼够 $hlen$ 比特转成整数，最后 $h_1 = (Ha \bmod (n-1)) + 1$。$H_2$ 一模一样，就是前缀换成 02。拿前缀字节把同一个 hash 掰成多个用途，和 KDF 里的计数器是一个思路。

生成算法

GB/T 38635.2中写：（标准原步骤，符号照抄）

A1：计算 $g = e(P_1, P_{pub\text{-}s})$；

A2：产生随机数 $r \in [1, N-1]$；

A3：计算 $w = g^r$，转比特串；

A4：计算 $h = H_2(M \Vert w, N)$；

A5：计算 $l = (r - h) \bmod N$，若 $l = 0$ 回到 A2；

A6：计算 $S = [l]d_{sA}$；

A7：输出 $(h, S)$。

输出格式和 SM2/ECDSA 的 $(r, s)$ 不一样，SM9 签名是 $(h, S)$：$h$ 是个 256 位整数（hash 值），$S$ 是 $G_1$ 上的点。

验证算法

B1：检查 $h' \in [1, N-1]$；

B2：检查 $S' \in G_1$；

B3：计算 $g = e(P_1, P_{pub\text{-}s})$；

B4：计算 $t = g^{h'}$；

B5：计算 $h_1 = H_1(ID_A \Vert hid, N)$；

B6：计算 $P = [h_1]P_2 + P_{pub\text{-}s}$（$G_2$ 的点）；

B7：计算 $u = e(S', P)$；

B8：计算 $w' = u \cdot t$，转比特串；

B9：计算 $h_2 = H_2(M' \Vert w', N)$，$h_2 = h'$ 就通过。

正确性一行推完：$u \cdot t$ 在指数上是 $l \cdot t_2 \cdot (h_1 + k_s) + k_s \cdot h' = l \cdot k_s + k_s \cdot h' = k_s \cdot (l + h') = k_s \cdot r$，而 $w = g^r = e(P_1, P_2)^{k_s r}$，两个相等，hash 后的 $h_2$ 自然等于 $h$。

密钥交换协议

加密体系的主密钥方向和签名正好反过来：KGC 随机 $k_e \in [1, N-1]$，算 $P_{pub\text{-}e} = [k_e]P_1$（这次是 $G_1$ 的点），用户加密私钥 $d_{eA} = [t_2]P_2$（$G_2$ 的点），$t_1 = (H_1(ID_A \Vert hid, N) + k_e) \bmod N$，$t_2 = k_e \cdot t_1^{-1} \bmod N$。

个人感觉这个方向设计是故意交叉的：签名的公钥侧把 $P_2$ 塞给了主公钥、加密反过来，两边负载均衡一下，毕竟 $G_2$ 的运算比 $G_1$ 贵。

A 发起（对端 B）：

A1：计算 $Q_B = [H_1(ID_B \Vert hid, N)]P_1 + P_{pub\text{-}e}$（$G_1$ 的点，就是拿 B 的身份当公钥）；

A2：产生随机数 $r_A \in [1, N-1]$；

A3：计算 $R_A = [r_A]Q_B$；

A4：把 $R_A$ 发给 B。

B 响应：

B1：计算 $Q_A = [H_1(ID_A \Vert hid, N)]P_1 + P_{pub\text{-}e}$；

B2：产生随机数 $r_B \in [1, N-1]$；

B3：计算 $R_B = [r_B]Q_A$；

B4：验证 $R_A \in G_1$，计算 $g_1 = e(R_A, d_{eB})$，$g_2 = e(P_{pub\text{-}e}, P_2)^{r_B}$，$g_3 = g_1^{r_B}$；

B5：计算 $SK_B = KDF(ID_A \Vert ID_B \Vert R_A \Vert R_B \Vert g_1 \Vert g_2 \Vert g_3, klen)$；

B6：（可选）$S_B = Hash(0x82 \Vert g_1 \Vert Hash(g_2 \Vert g_3 \Vert ID_A \Vert ID_B \Vert R_A \Vert R_B))$；

B7：把 $R_B$（和 $S_B$）发给 A。

A 验证再算：

A5：验证 $R_B \in G_1$，计算 $g_1' = e(P_{pub\text{-}e}, P_2)^{r_A}$，$g_2' = e(R_B, d_{eA})$，$g_3' = (g_2')^{r_A}$；

A6：（可选）按 $S_B$ 的公式算 $S_1$，验证 $S_1 = S_B$；

A7：计算 $SK_A = KDF(ID_A \Vert ID_B \Vert R_A \Vert R_B \Vert g_1' \Vert g_2' \Vert g_3', klen)$；

A8：（可选）算 $S_A = Hash(0x83 \Vert g_1' \Vert Hash(g_2' \Vert g_3' \Vert ID_A \Vert ID_B \Vert R_A \Vert R_B))$ 发给 B 验。

对称性一行推完：$e(R_A, d_{eB})$ 在指数上是 $r_A \cdot (h_B + k_e) \cdot k_e \cdot (h_B + k_e)^{-1} = r_A \cdot k_e$，和 $g_1' = e(P_{pub\text{-}e}, P_2)^{r_A}$ 相同，$g_2$ 与 $g_2'$ 同理，所以 $(g_1, g_2, g_3) = (g_1', g_2', g_3')$，两边 KDF 出同一个密钥。

KDF 和 SM2 那篇的一模一样（SM3 计数器模式，$ct$ 从 1 起，末块截断），没什么好说的。

密钥封装协议

A 封装给 B：

A1：计算 $Q_B = [H_1(ID_B \Vert hid, N)]P_1 + P_{pub\text{-}e}$；

A2：产生随机数 $r \in [1, N-1]$；

A3：计算 $C = [r]Q_B$，转比特串；

A4：计算 $g = e(P_{pub\text{-}e}, P_2)$；

A5：计算 $w = g^r$；

A6：计算 $K = KDF(C \Vert w \Vert ID_B, klen)$，全 0 回到 A2；

A7：输出 $(K, C)$。

B 解封装：

B1：验证 $C \in G_1$；

B2：计算 $w' = e(C, d_{eB})$，转比特串；

B3：计算 $K' = KDF(C \Vert w' \Vert ID_B, klen)$，全 0 报错；

B4：输出 $K'$。

一致性一行：$e(C, d_{eB}) = e([r]Q_B, d_{eB})$ 指数是 $r \cdot k_e$，和 $w = g^r$ 一样。

公钥加密算法

加密算法

消息 $M$（$mlen$ 比特），加密给 B：

A1：计算 $Q_B = [H_1(ID_B \Vert hid, N)]P_1 + P_{pub\text{-}e}$；

A2：产生随机数 $r \in [1, N-1]$；

A3：计算 $C_1 = [r]Q_B$，转比特串；

A4：计算 $g = e(P_{pub\text{-}e}, P_2)$；

A5：计算 $w = g^r$；

A6：计算 $K = KDF(C_1 \Vert w \Vert ID_B, klen)$，然后分两种模式：

(1) 基于 KDF 的序列密码模式：$klen = mlen + K2\_len$，$K_1$ 取 $K$ 最左 $mlen$ 比特，$K_2$ 取剩下的，$K_1$ 全 0 回到 A2，密文 $C_2 = M \oplus K_1$；

(2) 结合 KDF 的分组密码模式：$klen = K1\_len + K2\_len$（$K1\_len$ 得是 128 比特的倍数，Enc 就是 SM4），$C_2 = IV \Vert Enc(K_1, M, IV)$，IV 取 $K$ 的前 16 字节（非 ECB 模式才拼 IV），填充规则有点特别：把 $k - (mlen \bmod k)$ 这个数既当填充值又当填充个数，也就是永远垫 1 到 16 字节，解密看最后一字节就知道去掉几个；

A7：计算 $C_3 = MAC(K_2, C_2)$，这个 MAC 就是 $H_v(C_2 \Vert K_2)$，注意顺序是密钥拼在后面；

A8：输出 $C = C_1 \Vert C_3 \Vert C_2$。

和 SM2 那篇同一个坑：新标准是 $C_1 \Vert C_3 \Vert C_2$，老 GM/T 0044 年代的一些实现是 $C_1 \Vert C_2 \Vert C_3$，互操作对不上先查这个。

解密算法

B1：从 $C$ 里取出 $C_1$，验证 $C_1 \in G_1$；

B2：计算 $w' = e(C_1, d_{eB})$；

B3：按模式算 $M'$：序列密码模式 $M' = C_2 \oplus K_1'$（$K' = KDF(C_1 \Vert w' \Vert ID_B, mlen + K2\_len)$），分组密码模式 $M' = Dec(K_1', C_2)$（$K' = KDF(C_1 \Vert w' \Vert ID_B, K1\_len + K2\_len)$），$K_1'$ 全 0 报错；

B4：计算 $u = MAC(K_2', C_2)$，不等于 $C_3$ 报错；

B5：输出 $M'$。

相关攻击

(1) KGC 天生 key escrow：KGC 自己能算出任何人的私钥（能签能解密一切），主密钥一丢全系统沦陷。这是 IBC 的设计内伤，也是它一直推不开的原因之一。做题看到”KGC 和某一通信方串通”的设定别惊讶，是特性不是 bug。

(2) 拿到 $k_s$ 等于伪造任何人：私钥派生就一步 $t_2 = k_s (H_1 + k_s)^{-1}$，ID 随便填。反过来，拿到某个用户的 $d_{sA}$ 想反推 $k_s$，得先对 $d_{sA}$ 解 ECDLP 恢复 $t_2$（之后 $k_s = t_2 H_1 (1 - t_2)^{-1}$ 就是线性的事了），254 位素阶群上不现实。

(3) 方向别记反：签名主公钥在 $G_2$、签名私钥在 $G_1$；加密体系全反过来。写题对拍的时候两边群搞混，会出现每个值单独看都”对”、合起来验签死活不过的灵异现象，特别隐蔽。

(4) B1/B2 那种成员检查不是废话：不验 $S' \in G_1$、$C_1 \in G_1$，就可能吃 invalid curve / 小阶子群攻击（拿错曲线或者低阶点骗协议运算，一段段泄信息），这类题的突破口经常就是”实现少写了一行检查”。

(5) 嵌入次数是双刃剑：pairing 把 $G_1$、$G_2$ 上的 DLP 搬到 $\mathbb{F}_{q^{12}}$ 里去解，标准参数 $k = 12$ 是平衡过的安全点；但题目要是自定义曲线给了个很小的 $k$（2、4、6 这种），又让你算 pairing，基本就是明示 MOV 攻击，把椭圆曲线上的 DLP 转成有限域乘法群的 DLP，再用 index calculus 收掉。

(6) hid 和 ID 编码是互操作重灾区：hid 是域分离字节，签名和加密用不同的值，混用了派生出来的私钥直接对不上；ID 的编码方式（原始字符串还是带长度前缀）各家库也不统一，排错先把这个对齐。
