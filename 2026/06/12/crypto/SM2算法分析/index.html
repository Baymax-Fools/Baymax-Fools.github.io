SM2算法分析（国密学习 4/5）

注：本blog参考《SM2椭圆曲线公钥密码算法》系列标准（GB/T 32918.1-2016 ~ GB/T 32918.5-2017）与python开源库gmssl中的sm3算法实现

国家标准全文公开系统：https://openstd.samr.gov.cn

椭圆曲线的代码实现看着比较乱，所以本blog不展示完整的算法源码，点的运算推荐直接在sagemath里做，文末给了一份能直接跑的标准向量验证脚本

算法基本信息

SM2是国密的椭圆曲线公钥密码算法，对标的是国外那套ECC应用（ECDSA、ECDH、ECIES这些），不是一个单独的算法，是一族算法，GB/T里拆成了5个部分。

个人感觉是公开国密里最难的一个，用法也是最广的。所有部分的杂凑算法都搭配SM3，随机数发生器要求用国家密码管理局批准的。

数字签名算法

参数定义

先看一下标准里定义好的参数：

$G$：$(x_G,y_G)$，椭圆曲线上选取的一个阶为素数 $n$ 的基点

$d_A$：用户A的私钥，$d_A \in [1, n-1]$

$P_A$：$(x_A,y_A)$，用户A的公钥，$P_A = [d_A]G$

$[k]P$：椭圆曲线上点 $P$ 的 $k$ 倍点

$H_v(x)$：消息摘要，输出 $v$ 比特，SM2固定用SM3（$v=256$）

$a, b$：曲线参数，方程为 $y^2 = x^3 + ax + b$，定义在有限域 $F_q$ 上

$h$：余因子，$h = #E(F_q)/n$

再特别说一下 $Z_A$ 这个参数，SM2里到处都是它。用户A有长度为 $entlen_A$ 比特的可辨别标识 $ID_A$（真实场景里可能是邮箱、域名这些），$ENTL_A$ 是由 $entlen_A$ 转换成的两个字节，则

$Z_A = H_{256}(ENTL_A \Vert ID_A \Vert a \Vert b \Vert x_G \Vert y_G \Vert x_A \Vert y_A)$

可以看到 $Z_A$ 把用户身份、曲线参数、公钥全部绑在一起过了遍SM3

注：$ID_A$ 有个默认值 1234567812345678（标准示例和gmssl这些库都用它），$Z_A$ 是跟着 $ID_A$ 走的，userid对不上验证就全盘通不过，验签失败第一件事就是查双方userid是不是一致

生成算法

设待签名的消息为 $M$，签名者A生成签名 $(r,s)$：

  1. 置 $\bar{M} = Z_A \Vert M$
  2. 计算 $e = H_v(\bar{M})$，将 $e$ 的数据类型转换为整数
  3. 用随机数发生器产生随机数 $k \in [1, n-1]$
  4. 计算椭圆曲线点 $(x_1, y_1) = [k]G$，将 $x_1$ 的数据类型转换为整数
  5. 计算 $r = (e + x_1) \bmod n$，若 $r = 0$ 或 $r + k = n$，则返回A3重新取 $k$
  6. 计算 $s = ((1 + d_A)^{-1} \cdot (k - r \cdot d_A)) \bmod n$，若 $s = 0$，则返回A3
  7. 将 $r, s$ 转换为字节串输出，$(r,s)$ 即为消息 $M$ 的签名

和ECDSA不一样的地方主要有三个：

(1) $e$ 的来源：ECDSA是 $e = H(m)$ 直接杂凑消息；SM2杂凑的是 $Z_A \Vert M$，把用户标识、曲线参数、公钥都绑进去了，这也是验签必须知道对方 $ID_A$ 的原因
(2) $r$ 的构造：ECDSA的 $r$ 就是 $x_1 \bmod n$；SM2是 $(e + x_1) \bmod n$
(3) $s$ 的构造：ECDSA是 $s = k^{-1}(e + rd)$；SM2是 $s = (1+d)^{-1}(k - rd)$，私钥换了一种方式进入式子，这直接决定了k重用时恢复私钥的公式长得不一样（见文末CTF相关）

验证算法

收到 $M'$ 和 $(r', s')$ 后，验证者B执行：

B1：检验 $r' \in [1, n-1]$ 是否成立，不成立则验证不通过

B2：检验 $s' \in [1, n-1]$ 是否成立，不成立则验证不通过

B3：置 $\bar{M}' = Z_A \Vert M'$

B4：计算 $e' = H_v(\bar{M}')$，将 $e'$ 的数据类型转换为整数

B5：计算 $t = (r' + s') \bmod n$，若 $t = 0$ 则验证不通过

B6：计算椭圆曲线点 $(x_1', y_1') = [s']G + [t]P_A$

B7：计算 $R = (e' + x_1') \bmod n$，检验 $R = r'$ 是否成立，成立则验证通过

GB/T 32918.2中写：注：如果 $Z_A$ 不是用户A所对应的杂凑值，验证自然通不过

验证为什么是对的，其实一行就能推完。把生成算法A6的式子两边乘 $(1+d_A)$ 变形可得 $k = s(1+d_A) + rd_A$，于是

$$[s']G + [t]P_A = [s' + (r'+s')d_A]G = [s'(1+d_A) + r'd_A]G = [k]G$$

所以B6算出来的点就是签名时的 $[k]G$，$x_1' = x_1$，自然有 $R = (e'+x_1') = r$

密钥交换协议

对标ECDH，不过结构上更像ECMQV：双方的临时私钥不只参与一次乘法，还会通过对方临时公钥x坐标的折叠值参与计算，并且自带可选的密钥确认。A是发起方，B是响应方，双方事先商定好要派生的密钥长度 $klen$

先定义两个记号（32918.1总则里的）：

$w = \lceil \log_2(n)/2 \rceil - 1$（sm2p256v1上 $w = 127$），对点的x坐标做折叠：$\bar{x} = 2^w + (x \And (2^w - 1))$

用户A：

A1：产生随机数 $r_A \in [1, n-1]$

A2：计算 $R_A = [r_A]G = (x_1, y_1)$

A3：将 $R_A$ 发送给B

用户B：

B1：产生随机数 $r_B \in [1, n-1]$

B2：计算 $R_B = [r_B]G = (x_2, y_2)$

B3：计算 $\bar{x}_2 = 2^w + (x_2 \And (2^w - 1))$

B4：计算 $t_B = (d_B + \bar{x}_2 \cdot r_B) \bmod n$

B5：从 $R_A$ 取出 $x_1$，验证 $R_A$ 满足椭圆曲线方程，计算 $\bar{x}_1 = 2^w + (x_1 \And (2^w - 1))$

B6：计算 $V = [h \cdot t_B](P_A + [\bar{x}_1]R_A) = (x_V, y_V)$，若 $V$ 是无穷远点则协商失败

B7：计算 $K_B = KDF(x_V \Vert y_V \Vert Z_A \Vert Z_B, klen)$

B8（可选）：$S_B = Hash(0x02 \Vert y_V \Vert Hash(x_V \Vert Z_A \Vert Z_B \Vert x_1 \Vert y_1 \Vert x_2 \Vert y_2))$

B9：将 $R_B$（和可选的 $S_B$）发送给A

用户A：

A4：计算 $\bar{x}_1 = 2^w + (x_1 \And (2^w - 1))$

A5：计算 $t_A = (d_A + \bar{x}_1 \cdot r_A) \bmod n$

A6：从 $R_B$ 取出 $x_2$，验证 $R_B$ 满足椭圆曲线方程，计算 $\bar{x}_2 = 2^w + (x_2 \And (2^w - 1))$

A7：计算 $U = [h \cdot t_A](P_B + [\bar{x}_2]R_B) = (x_U, y_U)$，若 $U$ 是无穷远点则协商失败

A8：计算 $K_A = KDF(x_U \Vert y_U \Vert Z_A \Vert Z_B, klen)$

A9（可选）：$S_1 = Hash(0x02 \Vert y_U \Vert Hash(x_U \Vert Z_A \Vert Z_B \Vert x_1 \Vert y_1 \Vert x_2 \Vert y_2))$，检验 $S_1 = S_B$

A10（可选）：$S_A = Hash(0x03 \Vert y_U \Vert Hash(...))$ 发送给B，B同样验证

步骤看着有点乱，其实核心就是双方最后都能算出同一个点，一行推完：

$$[t_A](P_B + [\bar{x}_2]R_B) = [t_A \cdot (d_B + \bar{x}_2 r_B)]G = [t_A t_B]G$$

对B同理 $[t_B](P_A + [\bar{x}_1]R_A) = [t_B t_A]G$，两边算的是同一个点，过同一个KDF得到的密钥自然相同

公钥加密算法

对标ECIES：一次椭圆曲线运算 + KDF派生密钥流做对称加密 + 杂凑做完整性校验，三段密文一次出来

密钥派生函数KDF

本质就是SM3的计数器模式，没什么好说的（和ZUC那篇里用的是同一个KDF，定义在32918.1总则里）

输入比特串 $Z$ 和需要的密钥长度 $klen$：

a) 初始化32比特计数器 $ct = 0x00000001$

b) 对 $i = 1$ 到 $\lceil klen/v \rceil$：计算 $Ha_i = H_v(Z \Vert ct)$，并更新 $ct = ct + 1$

c) 若最后一块不完整（$klen/v$ 不是整数），取 $Ha_{\lceil klen/v \rceil}$ 最左边的 $klen - v \cdot \lfloor klen/v \rfloor$ 比特

d) $K = Ha_1 \Vert Ha_2 \Vert \cdots$

加密算法

设消息为长度 $klen$ 比特的比特串 $M$，加密者A用接收者B的公钥 $P_B$：

A1：产生随机数 $k \in [1, n-1]$

A2：计算椭圆曲线点 $C_1 = [k]G = (x_1, y_1)$，转换为比特串

A3：计算 $S = [h]P_B$，若 $S$ 为无穷远点则报错退出

A4：计算 $[k]P_B = (x_2, y_2)$

A5：计算 $t = KDF(x_2 \Vert y_2, klen)$，若 $t$ 为全0比特串则返回A1

A6：计算 $C_2 = M \oplus t$

A7：计算 $C_3 = Hash(x_2 \Vert M \Vert y_2)$

A8：输出密文 $C = C_1 \Vert C_3 \Vert C_2$

注：密文顺序是 $C_1 \Vert C_3 \Vert C_2$，老标准GM/T 0003-2012和一些老实现是 $C_1 \Vert C_2 \Vert C_3$，密文解不出来的时候先试试把32字节的 $C_3$（就是SM3摘要）换个位置，这是互操作排错的头号坑。另外 $C_1$ 转字节串有压缩（02/03开头33字节）和未压缩（04开头65字节）两种表示，标准示例用的是未压缩

解密算法

B1：从 $C$ 中取出 $C_1$，验证 $C_1$ 满足椭圆曲线方程，不满足则报错退出

B2：计算 $S = [h]C_1$，若 $S$ 为无穷远点则报错退出

B3：计算 $[d_B]C_1 = (x_2, y_2)$

B4：计算 $t = KDF(x_2 \Vert y_2, klen)$，若 $t$ 为全0比特串则报错退出

B5：从 $C$ 中取出 $C_2$，计算 $M' = C_2 \oplus t$

B6：计算 $u = Hash(x_2 \Vert M' \Vert y_2)$，从 $C$ 中取出 $C_3$，若 $u \neq C_3$ 则报错退出

B7：输出明文 $M'$

原理和ECDH一样：$[d_B]C_1 = [d_B k]G = [k]P_B$，两边各用手里的一对值算出同一个 $(x_2, y_2)$

相关攻击

曲线本身的一般攻击（异常曲线、Smart’s attack、小阶子群、MOV归约这些）在椭圆曲线算法-攻击那篇里写过，这里只说SM2特有的

(1) 签名k重用、泄漏

把签名式 $s = (1+d)^{-1}(k - rd)$ 两边乘 $(1+d)$ 变形：

$$s(1+d) = k - rd \Rightarrow d(r+s) = k - s \Rightarrow d = (k - s) \cdot (r+s)^{-1} \bmod n$$

k已知直接代入。同一个k签了两条不同的消息 $(r_1, s_1)$、$(r_2, s_2)$（同k时 $[k]G$ 一样但 $e$ 不同，所以SM2里 $r_1 \neq r_2$），由 $k = s_1(1+d) + r_1 d = s_2(1+d) + r_2 d$ 联立相减：

$$d = (s_2 - s_1) \cdot [(r_1 + s_1) - (r_2 + s_2)]^{-1} \bmod n$$

注意和ECDSA长得不一样（ECDSA是 $d = (s_1 - s_2)^{-1}(e_1 - e_2)$ 这种把差放在指数上），SM2的私钥恢复里 $s$ 在分子、$(r+s)$ 的差在分母

(2) 密文顺序和编码

$C_1 C_3 C_2$ 还是 $C_1 C_2 C_3$、$C_1$ 带不带04前缀、点坐标压不压缩，gmssl、BouncyCastle、自研实现互操作时的头号坑（见上文加密算法的注）

(3) userid不一致

$Z_A$ 把 $ID_A$ 绑进了签名、密钥交换和加密，双方默认值 1234567812345678 对不上就全盘验证不过，排错优先级第一

(4) 不验证点在曲线上

标准解密算法B1有”验证 $C_1$ 满足曲线方程”，密钥交换B5、A6也要求验证对方临时公钥。魔改实现常把这一步省掉，攻击者发一个不在曲线上或落在小子群里的点，骗出对方的 $[d_B]C_1$ 后用小步恢复 $d_B$（invalid curve、small subgroup attack）

(5) 自定义曲线

题目给自定义曲线（不是sm2p256v1）时优先查三件事：$p$ 或 $\#E(F_q)$ 有没有小因子（Pohlig-Hellman）、是不是anomalous曲线（$\#E(F_p) = p$，Smart’s attack直接解私钥）、嵌入度是不是很小（MOV归约到 $F_{p^k}$ 上的离散对数），手法都在椭圆曲线算法-攻击那篇里

(6) 跨算法、跨曲线复用私钥

同一个 $d$、同一个 $k$ 在ECDSA和SM2下各签一次，两组签名式联立可以直接解出 $d$（公开论文里有，CTF也出过类似的），跨曲线复用私钥同理。一句话：私钥永不复用
